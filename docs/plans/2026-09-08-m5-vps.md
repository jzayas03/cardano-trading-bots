# M5 implementation plan: the bot leaves the laptop

> Spec: `docs/specs/2026-09-08-m5-deployment.md`. Read it first; this argues from it.

**Goal:** the collector and the paper runs survive a reboot with no human, on a machine that does
not doze.

**Why now, in one measurement:** on 2026-09-08 the paper runs recorded **16 of 64 expected
boundaries** in 16 hours. The cause is not missing data — run 139's log shows **149
`stale candle skipped` against 4 `no candle at boundary`**. `liveFeed.ts:61` discards a candle when
`now - tickTs > maxGapMs`, so when the laptop dozes the paper process wakes late and throws away the
backlog. That behaviour is correct and must not be relaxed: you could not have traded on a
40-minute-old candle. The machinery is telling us the hardware is wrong.

**Host:** Hetzner CX22, Ashburn, Ubuntu 24.04 LTS. 2 vCPU / 4 GB / 40 GB against a footprint of a
67 MB database growing ~1.4 MB/day and ~216 MB resident across four node processes.

## Global constraints

- Never in czi-middleware's AWS account, and never sharing a blast radius with a HIPAA product.
- No secret enters the repo, an image, or a shell history. `.env` is placed by hand, mode 600.
- The dashboard stays bound to 127.0.0.1 and is reached over an SSH tunnel. No public port but SSH.
- Cutover (M5.5) happens only after a deliberate reboot proves the box comes back by itself.
- The running laptop week is not touched until M5.5, and is not the run M3 is declared from.

## Architecture, and what it deliberately copies

Postgres in Docker, exactly as `docker-compose.yml` runs it today. The collector and paper runs
under **systemd**, from a git checkout, with `tsx` — the direct analogue of the launchd agent
proven on 2026-09-08. Containerising the Node processes is out of scope in the spec and would mean
building images around Dexter's ESM quirks for no gain.

**Node comes from NodeSource apt, not nvm.** The launchd work established that a supervisor gets
none of a login shell: nvm cost us a wrapper that has to source `nvm.sh` itself. An apt-installed
`/usr/bin/node` removes that entire class of failure from every unit file.

## Task 1: `infra/vps/provision.sh` — bare Ubuntu to ready host

Idempotent, re-runnable, root. Creates the `ctb` service user; installs Docker, Node 24 from
NodeSource, git; enables `ufw` with SSH only; disables SSH password auth and root login; sets the
timezone to UTC so every log and every cron boundary matches the collector's clock.

Ends by printing what it did NOT do: place `.env`, clone the repo, or start anything.

## Task 2: systemd units

| Unit | Does |
|---|---|
| `ctb-collector.service` | the collector, `Restart=always` |
| `ctb-paper@.service` | one instance per strategy, e.g. `ctb-paper@ma-crossover` |
| `ctb-backup.service` + `.timer` | daily 03:30 UTC, the launchd agent's equivalent |
| `ctb-watch.service` + `.timer` | every 15 min; non-zero exit is the alarm |

**The paper unit cannot use a naive `Restart=always`.** A crashed run needs `--resume <id>` against
a specific run row, not a fresh run that would start a second equity curve for the same strategy.
So `ExecStart` calls `infra/vps/paper-start.sh`, which asks the database for a `running` row for
this strategy and resumes it, or starts a new run when there is none. The fresh-heartbeat refusal —
liveness-aware since #66 — is what makes that safe to automate: if a process really is still
running the row, the resume is refused and the unit fails loudly instead of double-writing.

## Task 3: `infra/vps/deploy.sh` — checkout to running

Clone or fast-forward, `npm ci`, `npm run migrate`, install the units, `daemon-reload`, enable.
Refuses to run if `.env` is absent or group/world-readable.

## Task 4: prove it survives a reboot

`reboot`, then confirm without touching anything: Postgres up, collector ticking, three paper runs
resumed against **their existing run ids**, backup timer armed, `npm run watch` silent. A unit that
comes back with a NEW run id has failed this task even though everything looks healthy.

## Task 5: monitoring that pushes

`watch` already exits non-zero with one line per problem. The timer turns that into a signal. Per
the spec's section 8, it must not alarm on a just-resumed run whose heartbeat still belongs to the
dead segment.

## Task 6: cutover (M5.5)

Stop the laptop's writers, `npm run backup`, restore on the host, verify row counts, start the
units, confirm the first tick lands, and only then declare the laptop free. The 7-day run restarts
here; the laptop run is a soak test, not M3 evidence.

## Out of scope

Live execution, wallet, signing, key custody. High availability. A second region. A public
dashboard. Terraform — one hand-provisioned box that is documented and reproducible beats an
unproven module.
