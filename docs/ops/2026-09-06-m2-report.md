## 4. Synthetic-depth paragraph and reference-strategy caveat

The external-history backtest (runs 1-4) used the `cpmm_synthetic_depth` fill
model with an **operator-declared** depth of 800,000 ADA (`--depth-ada 800000`),
not an observed on-chain reserve. `candles_external` (from GeckoTerminal) carries
OHLCV price and volume, but not the pool's actual reserve depth at each tick —
that data predates this collector's own observation window. The synthetic-depth
model applies the same constant-product fill math as the observed-reserves model,
but with a single, hand-picked depth held constant across the entire 3-month
backtest window, rather than the pool's true reserves at each point in time
(which fluctuated with other traders' activity, arbitrage, and liquidity
changes throughout June-August 2026). Every number in the run 3/4 summary table
— fills, slippage, fees, return, drawdown — is therefore a function of that one
declared-depth assumption as much as it is a function of the strategy or the
price history, and would change under a different declared depth. **This is a
plumbing check, not a strategy result:** the -58.31% return, 58.68% max
drawdown, and 166 filled orders for `ma-crossover` on SNEK over 2026-06-01 to
2026-09-01 demonstrate that the candle ingest -> strategy loop -> cpmm fill ->
cost model -> run/paper_orders provenance pipeline works end to end and
reproduces deterministically, not that this strategy is or isn't profitable —
no claim about the reference strategy's real-world edge should be drawn from
this run.

  removal covers V2 as well as V1; this needs a live-order check (e.g. an

  GeckoTerminal pool discovery for those tokens or the collector running long

  report, not derived from a price-feed-driven default as floated in the
  plan's open item #2; the resulting P&L numbers are sensitive to this choice
  and must not be read as a real backtest result (see §4).
